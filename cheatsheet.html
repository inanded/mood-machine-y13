Tensors

import torch
t = torch.tensor([[1, 2, 3], [4, 5, 6]])   # from a list: 2 rows, 3 columns
z = torch.zeros(3, 4, 4)                    # all zeros, shape (3, 4, 4)
t.shape                                     # torch.Size([2, 3])
t[0]                                        # first row (counting starts at 0)
t[:, 1]                                     # second column, every row
t * 0.5                                     # maths on every number at once
t.argmax()                                  # position of the biggest number
x.item()                                    # one-number tensor to an ordinary number
In plain English
  1. Bring in PyTorch with import torch. You only need this once, at the top of the notebook.
  2. Make a tensor from a list of numbers. A list of lists gives you rows and columns.
  3. Check its shape to see how many numbers it holds along each direction. A face is (3, 32, 32): three colours, 32 rows, 32 columns.
  4. Pick out parts with square brackets. [0] is the first row. [:, 1] means "every row, column 1".
  5. Do maths on the whole tensor at once. There's no need for a loop.
  6. Use argmax() to find where the biggest number is. That's how a guess becomes a mood.
  7. Use item() when you want a plain Python number back, for printing or comparing.

Values That Learn

w = torch.tensor(0.0, requires_grad=True)   # PyTorch tracks its gradient
loss.backward()                             # works out every gradient
w.grad                                      # the gradient for w
with torch.no_grad():                       # change w without recording it
    w -= learning_rate * w.grad             # step the opposite way to the gradient
w.grad.zero_()                              # wipe it before the next step
In plain English
  1. Make a value with requires_grad=True. This tells PyTorch you want it to learn, so it keeps track of every calculation that uses it.
  2. Work out the loss, a single number that says how wrong you are.
  3. Call loss.backward(). PyTorch works backwards through the calculation and finds the gradient for every learning value.
  4. Read the gradient from w.grad. A positive gradient means making w bigger makes the loss bigger.
  5. Change w a little in the opposite direction to the gradient. Do it inside torch.no_grad() so PyTorch doesn't count the change as part of the next calculation.
  6. Wipe the gradient with zero_(). If you don't, the next gradient is added on top of this one.

The Training Loop: One Value at a Time (Session 5)

w = torch.tensor(0.0, requires_grad=True)   # start both values at 0
b = torch.tensor(0.0, requires_grad=True)
learning_rate = 0.1                         # how big each step is
for step in range(1000):
    loss = ((w * x + b - y) ** 2).mean()    # 1. how wrong are we?
    loss.backward()                         # 2. find the gradients
    with torch.no_grad():                   # 3. step downhill
        w -= learning_rate * w.grad
        b -= learning_rate * b.grad
    w.grad.zero_()                          # 4. wipe the gradients
    b.grad.zero_()
In plain English
  1. Make the values that will learn, w and b, starting at 0.
  2. Choose a learning rate. Too big and the loss jumps about or grows. Too small and learning is very slow.
  3. Repeat the next four steps many times, here 1,000.
  4. Make predictions with w * x + b, compare them with the right answers y, and turn the errors into one loss number. Squaring makes every error positive. mean() averages them.
  5. Find the gradients with loss.backward().
  6. Move w and b a small step downhill: subtract the learning rate times the gradient.
  7. Wipe both gradients, ready for the next time round.
  8. After the loop, print w and b to see what they learned.

Building a Network (Session 7)

from torch import nn

class MoodNet(nn.Module):
    def __init__(self, hidden=256):                     # build the layers
        super().__init__()
        self.flatten = nn.Flatten()                     # face to one long row
        self.hidden1 = nn.Linear(3 * 32 * 32, hidden)   # inputs, neurons
        self.hidden2 = nn.Linear(hidden, 128)           # must match the layer before
        self.output = nn.Linear(128, 10)                # one score per mood
        self.relu = nn.ReLU()

    def forward(self, x):                               # how a face flows through
        x = self.flatten(x)
        x = self.relu(self.hidden1(x))
        x = self.relu(self.hidden2(x))
        return self.output(x)

model = MoodNet().to(device)       # build it and move it to the device
In plain English
  1. Start a class that is a kind of nn.Module. That gives it everything PyTorch needs for training.
  2. In __init__, make each layer once and give it a name.
  3. Flatten first: a face is 3 × 32 × 32, and a Linear layer needs one long row of 3,072 numbers.
  4. Each nn.Linear(a, b) takes a numbers in and gives b numbers out. The number going into each layer must equal the number coming out of the one before.
  5. Finish with 10 outputs, one score for each mood.
  6. In forward, say the order a face goes through: flatten, first layer then ReLU, second layer then ReLU, then the output layer.
  7. Don't put ReLU after the output layer. The scores can be negative, and the loss function needs them as they are.
  8. Build the model with MoodNet() and move it to the same device as the data.

Loss, Optimiser and Batches

from torch.utils.data import DataLoader, Subset

loss_fn = nn.CrossEntropyLoss()                                    # the loss for choosing a class
optimiser = torch.optim.Adam(model.parameters(), lr=0.001)         # updates every weight for you

train_loader = DataLoader(train_faces, batch_size=64, shuffle=True)   # shuffle training data
part = Subset(train_faces, range(10000))                              # the first 10,000 faces
In plain English
  1. Choose the loss. CrossEntropyLoss is the one to use when the model picks one class out of several, like one mood out of ten.
  2. Make an optimiser and hand it all the model's weights with model.parameters(). It does the "step downhill" for every weight at once. Adam with a learning rate of 0.001 is a good place to start.
  3. Wrap the faces in a DataLoader. It serves them in batches, here 64 at a time.
  4. Shuffle the training faces so each epoch sees them in a new order. You don't need to shuffle validation or test faces.
  5. Use Subset to take part of a dataset, for example to keep some faces back for validation.

The Training Loop: Batches (Sessions 8 and 11)

model.train()                         # training mode
for faces, moods in train_loader:     # one batch at a time
    faces, moods = faces.to(device), moods.to(device)
    guesses = model(faces)            # 1. make guesses
    loss = loss_fn(guesses, moods)    # 2. how wrong were they?
    optimiser.zero_grad()             # 3. wipe old gradients
    loss.backward()                   # 4. find new gradients
    optimiser.step()                  # 5. nudge the weights
In plain English
  1. Put the model in training mode.
  2. Take one batch of faces and their right moods from the loader.
  3. Move both to the same device as the model.
  4. Give the faces to the model to get its guesses.
  5. Compare the guesses with the right moods to get the loss.
  6. Wipe the old gradients.
  7. Find the new gradients with loss.backward().
  8. Let the optimiser nudge every weight.
  9. Go back to step 2 until every batch has been used. That's one epoch.
  10. To train for several epochs, put the whole loop inside for epoch in range(epochs):, then check the accuracy after each one.

Marking, Saving and Loading

score = check_accuracy(model, val_loader)                  # percentage right
torch.save(model.state_dict(), "my_best.pth")              # save the learned numbers
model.load_state_dict(torch.load("my_best.pth", weights_only=True))   # put them back
model.eval()                                               # marking mode
In plain English
  1. Mark the model on faces it hasn't learned from, usually the validation faces, to get a percentage right.
  2. If that's your best score so far, save the model's learned numbers to a file.
  3. Later, build a model of the same shape and load the saved numbers into it.
  4. Switch to marking mode with model.eval() before you use it to make guesses.

Three Piles of Data

Pile Use it to How often
Training change the weights every epoch
Validation compare settings and choose the best after every run
Test report the final score once, at the very end

When Something Goes Wrong

What you see Likely cause Fix
NameError: name 'x' is not defined A cell above wasn't run Run the cells above, from the top
IndentationError Lines inside a loop or function aren't lined up Use four spaces for each level
mat1 and mat2 shapes cannot be multiplied A layer gets the wrong number of inputs Check the first number in each nn.Linear matches the size coming in
Expected all tensors to be on the same device The model and the data are in different places Add .to(device) to both
element 0 of tensors does not require grad A value can't learn Add requires_grad=True
The loss grows, or becomes nan Learning rate too big, or gradients not wiped Try a learning rate 10 times smaller; check zero_grad()
The loss never changes optimiser.step() is missing, or outside the loop Put all five steps inside the loop
Accuracy about 10% The model is guessing: it hasn't trained Check that the training loop ran
